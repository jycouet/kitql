A local PostgreSQL server as a **dev dependency**: no system install, no docker, no devbox. It works
offline once in your package manager store, on Windows, Linux (incl. WSL) and macOS.

- **One server per repo**: its data lives in the main worktree (`.git/kitql-postgres`), so every
  git worktree reuses the same server, on a fixed port.
- **One database per worktree**: named `<repo>_<worktree>`, every command targets the current
  worktree's database by default.

## Installation

```sh
npm i -D @kitql/postgres
```

## Usage

```sh
kitql-pg up      # start the server in the foreground (Ctrl+C stops it cleanly)
kitql-pg init    # in another terminal: create this worktree's database
```

`up` tells you when it is up and running, and `init` prints the url to put in your `.env`:

```sh
✔ myapp server up and running (PostgreSQL 18.6, port 5432, ~/code/myapp/.git/kitql-postgres/data)
  DATABASE_URL=postgres://postgres:postgres@localhost:5432/myapp_main
```

`init` is idempotent and sets the database timezone to UTC. Want another one?
`kitql-pg init --tz Europe/Paris`: it is kept by the next `init` and copied by `clone`.

| Command          | What it does                                                         |
| ---------------- | -------------------------------------------------------------------- |
| `up`             | create the cluster if needed and start it (foreground)               |
| `stop`           | stop the server (when the `up` terminal was killed)                  |
| `init`           | create the worktree database (idempotent, timezone UTC)              |
| `clone <from>`   | replace the worktree database by a copy of `<from>` (db or worktree) |
| `drop`           | drop the worktree database                                           |
| `ls`             | list databases (`*` = current worktree)                              |
| `dump [file]`    | `pg_dump -Fc -Z zstd` (default file: `<db>.dump`)                    |
| `restore <file>` | restore a `.dump` (pg_restore) or `.sql` (psql) in the worktree db   |
| `psql [-- args]` | open psql on the worktree database                                   |
| `url`            | print the connection url                                             |

Options: `-d, --db <name>` to target another database, `-p, --port <port>` (on `up`, remembered
for the repo), `--tz <zone>` (on `init`), `-f, --force`.

<Aside type="tip">
	`clone` uses `CREATE DATABASE x TEMPLATE y STRATEGY FILE_COPY`: the source must have no open
	connection. Stop your dev server / psql, or use `--force` to close them.
</Aside>

## Speed

The server is tuned for dev (`wal_level = minimal`, `synchronous_commit = off`, bigger WAL and
`maintenance_work_mem`; `fsync` stays on, so no corruption risk), `dump` uses zstd and `restore`
runs in a single transaction (all or nothing). On Windows, for a 680 MB database (3M rows,
4 indexes, 1 FK):

| Command   | Time | Plain PostgreSQL defaults |
| --------- | ---- | ------------------------- |
| `dump`    | 6s   | 24s (gzip)                |
| `restore` | 22s  | 36s                       |
| `clone`   | 7s   | 22s                       |

## Several projects

Each repo has its own server, data and port. Give the second project another port once, it is
remembered:

```sh
cd ~/code/app-a && kitql-pg up              # 5432
cd ~/code/app-b && kitql-pg up --port 5433  # 5433, at the same time
```

## Binaries

On first use, `kitql-pg` downloads PostgreSQL 18.6 from
[theseus-rs/postgresql-binaries](https://github.com/theseus-rs/postgresql-binaries) for your
platform (`win32-x64`, `linux-x64`, `linux-arm64`, `darwin-arm64`, `darwin-x64`), checks its
pinned sha256 and keeps it in a per-user cache shared by all your projects (only the binaries are
shared). After that first run, everything works offline.

To use another PostgreSQL (the system one, another version...), point `KITQL_PG_BIN` to its `bin`
folder. `KITQL_PG_CACHE` moves the binaries cache, `KITQL_PG_HOME` the data folder.
